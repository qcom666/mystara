# Запуск и тест Mini App в Telegram

Готового «файла бота» тут не будет — Telegram Mini App это веб-приложение
(уже полностью готово, весь код в этом репозитории), которое Telegram
открывает по обычной HTTPS-ссылке внутри бота. Чтобы это заработало, нужны
три вещи:

1. Бот, зарегистрированный через **@BotFather**.
2. Публичный **HTTPS**-адрес, по которому Telegram сможет достучаться до
   приложения (`localhost` не подходит — Telegram его не увидит).
3. Токен бота, добавленный в `.env` как `TELEGRAM_BOT_TOKEN` — он нужен
   нашему коду, чтобы проверять подпись `initData` (см.
   `src/lib/telegram/validate-init-data.ts`).

## Шаг 1 — создать бота

В Telegram открой **@BotFather** и напиши:

```
/newbot
```

Дай боту имя и username (username должен заканчиваться на `bot`, например
`mystara_tarot_bot`). BotFather пришлёт **токен** вида
`123456789:AAExampleTokenValue` — сохрани его, он понадобится в шаге 4.

## Шаг 2 — получить публичный HTTPS-адрес

Есть два пути. Автоматически поднять туннель из этой песочницы не вышло —
и `localtunnel`, и `cloudflared` в этой сети ведут себя нестабильно
(cloudflared падает на DNS-запросе, localtunnel периодически не может
достучаться до localhost). Дальше — рабочие варианты.

### Вариант A — задеплоить на Vercel (надёжнее, не зависит от туннелей)

Это то, ради чего архитектура проекта и делалась (см.
`PROJECT_ARCHITECTURE.md`, раздел Deployment). Из корня проекта:

```bash
npx vercel
```

Команда попросит войти (откроет ссылку в браузере — просто следуй ей и
залогинься/зарегистрируйся сама/сам, это должен сделать владелец аккаунта)
и предложит несколько вопросов с вариантами по умолчанию — можно просто
жать Enter. В конце Vercel даст постоянный адрес вида
`https://taro-project-xxxx.vercel.app` — его и используем в шаге 3.

После первого деплоя добавь переменные окружения в панели Vercel
(Project → Settings → Environment Variables) — как минимум `AUTH_SECRET` и
`TELEGRAM_BOT_TOKEN` (см. `.env.example` для остальных, все опциональны).

### Вариант B — туннель со своей машины (быстрее, но временно)

Если запускать `npm run dev` не в этой песочнице, а в обычном терминале на
своём компьютере, сеть там другая и туннель, скорее всего, просто заработает:

```bash
npx localtunnel --port 3000
```

Отдаст ссылку вида `https://xxxx.loca.lt`. **Важно:** при первом заходе на
неё (в том числе из Telegram) localtunnel показывает страницу-предупреждение
«Tunnel website ahead» и просит ввести показанный IP — это одноразово на 7
дней для одного IP. Проще всего один раз открыть ссылку в обычном браузере
на том же устройстве/сети, пройти через эту страницу, и после этого Telegram
(если открывать с того же адреса/сети) должен грузить приложение напрямую.

Альтернатива без этой страницы — `cloudflared`:

```bash
npx cloudflared tunnel --url http://localhost:3000
```

(тоже не требует регистрации; просто в этой песочнице у него не получилось
пройти DNS-проверку — на обычной сети должно быть без проблем).

Учти: адрес от туннеля меняется при каждом перезапуске — придётся заново
прописывать его в BotFather (шаг 3).

## Шаг 3 — прописать Mini App в BotFather

В @BotFather:

```
/mybots
```

→ выбери своего бота → **Bot Settings** → **Menu Button** → **Configure
menu button** → пришли полученный HTTPS-адрес (из шага 2) как URL, и
любой текст для кнопки (например «Открыть»).

Так у бота появится постоянная кнопка меню, которая открывает Mini App.

## Шаг 4 — добавить токен в `.env`

В файле `.env` в корне проекта (создан ранее в этой сессии) добавь строку:

```
TELEGRAM_BOT_TOKEN="токен_из_шага_1"
```

Если тестируешь через Vercel — добавь ту же переменную в Vercel
(Project → Settings → Environment Variables) и сделай redeploy.

## Шаг 5 — открыть и проверить

Найди своего бота в Telegram (по username) → **Start** → нажми кнопку меню
внизу. Должен открыться таргет-хаб (Tarot / Numerology / Astrology).

Что можно проверить:
- Шапка/футер сайта скрыты — их заменяет собственный хаб Mini App
  (`src/components/telegram/telegram-home.tsx`).
- Кнопка «Назад» в самом Telegram работает и ведёт по шагам флоу назад.
- Основные действия (перемешать, продолжить, сохранить) — те же золотые
  кнопки, что и на сайте, в самом контенте; нативной синей кнопки Telegram
  (MainButton) в приложении нет.
- Вход в аккаунт происходит автоматически, без пароля (проверка `initData`
  на сервере, см. `src/lib/auth.ts` → провайдер `telegram`) — но **только
  если** есть `DATABASE_URL` (см. `.env.example`); без базы данных вход не
  сработает, а сама Tarot/нумерология/астрология всё равно будет работать
  как у гостя.

## Если что-то не так

- Пустой экран / ошибка загрузки → проверь, что адрес из шага 2 реально
  открывается в обычном браузере (не только localhost).
- Кнопка меню не появляется → подожди немного, Telegram кэширует настройки
  бота; либо перезайди в чат с ботом.
- Вход не работает → проверь `TELEGRAM_BOT_TOKEN` совпадает с токеном от
  BotFather, и что `DATABASE_URL` настроен (иначе вход по дизайну отключён,
  см. `PROJECT_ARCHITECTURE.md` §24).

## Ответы бота в чате (вебхук)

Mini App открывается и без этого, но чтобы бот отвечал на `/start` и `/help`
кнопкой «Открыть Mystara», нужен вебхук — `src/app/api/telegram/webhook/route.ts`
(тексты ответов — `src/lib/telegram/bot-reply.ts`). Токен ему не нужен: ответ
уходит прямо в ответе на запрос Telegram.

1. Придумай длинный случайный секрет (буквы и цифры, до 256 символов) и добавь
   в Vercel переменную `TELEGRAM_WEBHOOK_SECRET` с этим значением. Сделай redeploy.
2. Один раз зарегистрируй вебхук (подставь свои значения — токен и секрет не
   публикуй и не отправляй в чаты):

   ```
   https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://taroproject.vercel.app/api/telegram/webhook&secret_token=<SECRET>
   ```

   Ответ должен быть `{"ok":true,...}`. Проверить: `.../bot<TOKEN>/getWebhookInfo`.
3. Напиши боту `/start`.

Без секрета вебхук отвечает 503, с неверным — 403: посторонние управлять ботом не могут.
