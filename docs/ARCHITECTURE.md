# Архитектура Mystara

Документ описывает, как устроено приложение: слои, потоки данных и правила, которые стоит
соблюдать при доработке. Установка и запуск описаны в [README](../README.md).

## 1. Общая картина

Один код на Next.js обслуживает две оболочки: обычный сайт и мини-приложение Telegram. Бот
(`/api/telegram/webhook`) отвечает в чате и открывает Mini App по кнопке. Внутри Telegram приложение
определяет себя по `window.Telegram.WebApp` и меняет только оболочку (шапка, кнопка «назад», нижняя
панель действий, способы оплаты); страницы, API и предметная область общие.

```text
Браузер / Telegram Mini App
        │
        ▼
  src/app (страницы, API)  ──►  src/components (интерфейс)
        │                              │
        ▼                              ▼
  src/lib (БД, авторизация,       src/modules (предметная область:
  оплата, Telegram, право)         таро, нумерология, астрология, ИИ)
        │
        ▼
   PostgreSQL (Prisma)
```

Правило слоёв: `src/modules` не импортирует ни Next.js, ни React, ни базу. Это чистый TypeScript,
который можно вызвать из бота, из фонового процесса или из теста. Интерфейс обращается к модулям
и никогда не переписывает их логику (тасование, подсчёт чисел, толкование).

## 2. Каталоги

| Каталог | Назначение |
|---|---|
| `src/app` | Маршруты Next.js. Страницы тонкие: собирают компоненты и вызывают модули |
| `src/app/api` | Обработчики API (см. раздел 6) |
| `src/components` | Интерфейс: `ui` (базовые элементы), `tarot`, `reading`, `numerology`, `astrology`, `telegram`, `legal`, `marketing`, `auth`, `shared` |
| `src/modules` | Предметная область: `tarot`, `numerology`, `astrology`, `ai`, `fun-facts`, `subscriptions` |
| `src/lib` | Инфраструктура: `db`, `auth`, `payments`, `pricing`, `telegram`, `legal`, `repositories`, `validation`, `i18n`, `rng`, `analytics` |
| `src/store` | Состояние текущего расклада в браузере (Zustand) |
| `prisma` | Схема и миграции приложения |
| `db` | Локальная разработка с базой и отдельная полная SQL-схема `mystara` (см. `db/README.md`) |
| `scripts` | Миграции при сборке на Vercel, выгрузка контента в SQL |

## 3. Таро

Колода (78 карт) и расклады лежат статическими, проверяемыми типами данными в
`src/modules/tarot/domain`, а не в базе: содержимое версионируется вместе с кодом, а в базе
хранятся только ссылки на него по строковым идентификаторам.

- **Расклады** описаны данными (`spreads.data.ts`): число карт, позиции, категория, сложность,
  признак платного. Новый расклад добавляется без правок движка; для макета есть общая адаптивная
  сетка, а для отдельных раскладов (например, Кельтского креста) — собственная раскладка по `spread.id`.
- **Движок раздачи** (`services/draw-engine.ts`) использует генератор с зерном (`lib/rng.ts`,
  mulberry32 с хешированием строки FNV-1a). `Math.random()` в предметной логике не применяется.
  Колода перемешивается алгоритмом Фишера — Йетса, карты берутся с начала без возвращения, поэтому
  повторов быть не может; положение карты (прямое или перевёрнутое, 30 % перевёрнутых) выбирается
  тем же потоком случайных чисел. Раздача идёт в браузере, без обращения к серверу.
- **Сохранённый расклад не пересчитывается.** В `ReadingCard` пишутся выбранные карта, позиция и
  положение; показ всегда идёт по этим строкам. Зерно хранится только как сведения о происхождении,
  поэтому изменение алгоритма тасования не может исказить старые расклады.
- **Гость** проходит расклад целиком; сохранить его предлагается после входа.

## 4. ИИ-толкование

Интерфейс `AIInterpretationProvider` (`src/modules/ai`) скрывает конкретную модель:

- `MockProvider` — детерминированный офлайн-вариант: собирает осторожный, непредсказательный текст
  из настоящих значений карт (выбирая любовь, карьеру, финансы или духовность по словам вопроса).
  Это провайдер по умолчанию, поэтому приложение работает без ключа.
- `AnthropicProvider` — вызывает API Anthropic только на сервере, требует строго структурированный
  ответ и проверяет его Zod до отправки клиенту. Модель задаётся `ANTHROPIC_MODEL`. Системная
  инструкция фиксирует рамку «размышление, а не предсказание» и запрещает категоричные обещания о
  финансах, здоровье и праве.
- Фабрика выбирает Anthropic, если задан `ANTHROPIC_API_KEY`, иначе Mock. Вызывается только из
  `/api/ai/interpret`; ключ в клиентскую сборку не попадает. Если провайдер упал (таймаут, плохой
  ответ, лимит), маршрут для этого запроса переходит на Mock, и пользователь всё равно получает
  толкование.

## 5. Нумерология и астрология

Обе области построены так же, как таро: статические данные и чистые функции расчёта.

- **Нумерология** (`src/modules/numerology`): число жизненного пути, число дня рождения и восемь
  чисел по имени (выражение, стремление души, личность, зрелость) в двух системах — Пифагора и
  халдейской. Хранится результат целиком, обе системы рядом.
- **Астрология** (`src/modules/astrology`): знак Солнца и признак секты (день или ночь) для бесплатного
  сценария; натальная карта — платная.
- **Натальная карта** считается по эфемеридам (`astronomia`): положение планет, асцендент и MC,
  дома по знакам (whole sign), аспекты с едиными допусками для каждого типа аспекта. Местное время
  рождения переводится в UTC по зоне IANA выбранного места (`resolve-birth-instant.ts`). Если время
  рождения неизвестно, дома, асцендент и MC не считаются, а не угадываются. Поправка ΔT принята
  равной нулю: для задач этого продукта точности достаточно. Список городов намеренно неполный:
  города добавляются по одному и только с проверенной часовой зоной.
- **Факт об актёре** (`src/modules/fun-facts`) связывает знак или число с известным человеком; это
  общий слой для нумерологии и астрологии.

## 6. API

Каждый изменяющий маршрут проверяет тело запроса Zod-схемой (`src/lib/validation`), определяет
пользователя по серверной сессии (идентификатор от клиента не принимается) и проверяет владение
ресурсом.

| Маршрут | Методы | Назначение |
|---|---|---|
| `/api/auth/[...nextauth]` | GET, POST | Обработчики Auth.js |
| `/api/auth/signup` | POST | Регистрация по e-mail и паролю |
| `/api/readings` | GET, POST | Список и сохранение раскладов |
| `/api/readings/[id]` | GET, PATCH | Один расклад; переключение избранного |
| `/api/favorites` | GET, POST, DELETE | Избранные карты и расклады |
| `/api/ai/interpret` | POST | ИИ-толкование расклада |
| `/api/numerology`, `/api/astrology` | GET, POST | Сохранение и история результатов |
| `/api/natal-chart` | GET, POST | Построение и история натальных карт |
| `/api/payments/methods` | GET | Доступные способы оплаты для текущей оболочки |
| `/api/payments/checkout` | POST | Создание покупки и платёжной ссылки |
| `/api/payments/yookassa/webhook` | POST | Уведомления ЮKassa об оплате |
| `/api/privacy/consent` | POST | Запись согласия на обработку данных |
| `/api/telegram/webhook` | POST | Вебхук бота: команды, предоплата и оплата Звёздами |

## 7. Авторизация

Auth.js v5 с JWT-сессиями и адаптером Prisma. Провайдеры:

- пароль (e-mail и хеш bcrypt);
- Google OAuth — подключается, только если заданы `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`;
- Telegram — принимает `initData` из Mini App и проверяет подпись HMAC-SHA256 токеном бота
  (`src/lib/telegram/validate-init-data.ts`). Подпись и есть учётные данные: при успехе находится или
  создаётся `User` по `telegramId`.

В сессии лежат `id` и `planTier`; тариф записывается в JWT при входе, чтобы проверка прав не
требовала обращения к базе на каждый запрос.

## 8. База данных

Схема приложения — `prisma/schema.prisma`: стандартные модели Auth.js (`User`, `Account`,
`Session`, `VerificationToken`) и продуктовые (`Reading`, `ReadingCard`, `AIInterpretation`,
`Favorite`, `Subscription`, `NumerologyReading`, `AstrologyReading`, `NatalChartReading`,
`NatalChartPurchase`).

- Дневной лимит бесплатных раскладов считается по числу строк `Reading` за сутки: отдельная
  таблица событий не нужна.
- Клиент Prisma 7 работает через драйверный адаптер `PrismaPg` с небольшим пулом (3 соединения на
  экземпляр функции, `DATABASE_POOL_MAX` меняет значение), потому что на serverless каждый экземпляр
  открывает собственный пул.
- Без `DATABASE_URL` приложение запускается, а маршруты, которым нужна база, отвечают понятной
  ошибкой (`isDatabaseConfigured()`).
- Миграции при сборке на Vercel выполняет `scripts/migrate-if-configured.mjs`: по прямой ссылке
  `DATABASE_URL_UNPOOLED`, если она есть. Если база не настроена, шаг пропускается.
- Отдельная полная SQL-схема `mystara` (бот, платежи, рассылки, аналитика, функции `fulfill_payment`,
  `refund_payment`, `anonymize_user`) описана в `db/mystara/README.md`. Приложение пока работает на
  схеме Prisma.

## 9. Лимиты и тарифы

`modules/subscriptions/usage-limit.service.ts` содержит чистую функцию `canStartReading` и таблицу
`PLAN_POLICIES`: бесплатный тариф — 3 расклада в день без платных раскладов, Premium — без
ограничений. Платные расклады помечены `isPremium` в данных. Интеграция платёжного провайдера для
подписки не меняет сигнатуру функции и не требует правок кода таро.

## 10. Оплата

Каталог способов — `src/lib/payments/catalog.ts`, функция `enabledProviders(env, context)`:

| Способ | Где доступен | Валюта | Цена |
|---|---|---|---|
| Звёзды Telegram (`stars`) | только бот и Mini App | XTR | 500 ⭐ |
| ЮKassa — карты и СБП (`yookassa`) | только сайт | RUB | 1000 ₽ за пакет из 3 карт |

Звёзды вынесены за пределы сайта, потому что Telegram требует их для цифровых товаров внутри своих
приложений. Криптовалюты и иностранной валюты нет сознательно: приём цифровой валюты за услуги в РФ
запрещён статьёй 14 закона 259-ФЗ. Способ включается сам, когда заданы его ключи. Подписка Premium
стоит 300 ₽ в месяц; цены во всех языках показываются в рублях (`lib/pricing`).

Обработка платежа:

1. `POST /api/payments/checkout` создаёт `NatalChartPurchase` со статусом `pending` и возвращает
   ссылку на оплату (для Звёзд — счёт, открываемый `WebApp.openInvoice`).
2. Для Звёзд Telegram присылает вебхуку бота `pre_checkout_query` (ответить нужно за 10 секунд;
   `isPurchasePayable` проверяет, что покупка существует, не оплачена и цена совпадает), а затем
   `successful_payment`. Для ЮKassa приходит уведомление `payment.succeeded`.
3. `fulfillPurchase` (`repositories/purchase.repository.ts`) начисляет кредиты: условное обновление
   статуса `pending → paid` в транзакции, идемпотентно при повторной доставке, с проверкой
   провайдера, суммы и валюты. Уникальный ключ `(provider, externalId)` не даёт записать одну
   транзакцию дважды.

Натальная карта доступна только по оплате: `POST /api/natal-chart` требует входа и положительного
остатка кредитов (иначе 401 или 402), а клиент (`NatalChartFlow`) до оплаты показывает панель покупки.
Обхода оплаты нет ни на сервере, ни на клиенте.

## 11. Telegram

- **Типы** (`src/lib/telegram/types.ts`) описывают только ту часть JS API WebApp, которая реально
  используется, без пакета-обёртки.
- **`TelegramProvider`** подключает `telegram-web-app.js`, вызывает `ready()` и `expand()`, подгоняет
  цвета шапки и фона под тему и автоматически входит по `initData`. Вне Telegram `webApp` равен
  `null`, и приложение ведёт себя как обычный сайт.
- **Оболочка.** Внутри Telegram `SiteHeader` и `SiteFooter` не отображаются; `TelegramGate` вместо
  лендинга показывает `TelegramHome`; `TelegramBackButton` связывает нативную кнопку «назад» с
  роутером.
- **Главное действие экрана** оформлено компонентом `PrimaryActionBar`. На сайте это обычная
  обёртка, а внутри Telegram те же золотые кнопки через портал выносятся в панель, закреплённую
  внизу. Портал нужен потому, что `position: fixed` ломается внутри элементов с `transform` или
  `backdrop-filter` (стеклянные панели). Кнопка отправки формы в панели обязана иметь `form="<id>"`,
  ведь в DOM она уже не внутри `<form>`.
- **Бот** (`src/lib/telegram/bot-reply.ts`) — чистая функция: из обновления Telegram она строит ответ,
  который обработчик возвращает телом ответа вебхука, поэтому бот не делает исходящих запросов и не
  хранит токен для ответов. В каждом ответе есть кнопки юридических документов; команды `/docs` и `/support` присылают документы и контакты поддержки.
- Вебхук принимает только запросы с верным `TELEGRAM_WEBHOOK_SECRET`.

## 12. Право и персональные данные

- Тексты оферты, политики конфиденциальности и согласия лежат в `src/lib/legal`; версия документов
  сейчас `2026-10-06`. Реквизиты оператора берутся из `NEXT_PUBLIC_OPERATOR_*`; пока они не заданы,
  страницы показывают заметные заглушки.
- Согласие на обработку данных фиксируется при регистрации и в Mini App: время и версия политики
  пишутся в `User.privacyConsentAt` и `User.privacyPolicyVersion` (152-ФЗ, ст. 9).
- Ссылки на документы есть в подвале сайта и в кнопках бота.
- Ограничения, которые нужно закрыть до запуска: хранение данных граждан РФ в базе на территории РФ
  (152-ФЗ, ст. 18, ч. 5), уведомление Роскомнадзора, проверка текстов юристом; политика должна
  соответствовать реальной инфраструктуре (хостинг, база, поставщик ИИ, аналитика).

## 13. Интернационализация

Два языка: английский и русский (`src/lib/i18n`). Переключатель в шапке меняет весь сайт сразу, без
перезагрузки; выбор хранится в `localStorage` устройства и в аккаунт не синхронизируется. Русские
тексты карт, толкований и фактов лежат рядом с английскими данными в модулях. Серверные
метаданные (`<title>`, JSON-LD) строятся до определения языка и остаются английскими.

## 14. SEO

Метаданные через Metadata API на каждой странице, `sitemap.ts` и `robots.ts`, построенные по тем же
данным, что и интерфейс (каждая карта и расклад попадают в sitemap), осмысленная семантическая
вёрстка и статические страницы `/tarot/cards/[slug]` и `/tarot/spreads/[slug]` через
`generateStaticParams`.

## 15. Аналитика

`lib/analytics.ts` предоставляет одну функцию `track(event, payload)` с типизированным набором
событий. Сейчас в разработке она пишет в консоль, в продакшене — пустышка; подключение сервиса
аналитики сводится к правке этого файла.

## 16. Развёртывание

Vercel (регион `fra1`), сборка командой `vercel-build`. Подробности — в README. CI на GitHub Actions
запускает проверку типов, линтер, тесты и сборку на каждый пуш в `main` и каждый pull request.

## 17. Что ещё не сделано

- Компонентные и сквозные тесты (Playwright).
- Ограничение частоты запросов к API и мониторинг ошибок.
- Подтверждение e-mail и сброс пароля.
- Самостоятельное удаление аккаунта и отзыв согласия пользователем (сейчас по письму оператору).
- Страницы просмотра сохранённых нумерологических, астрологических и натальных результатов.
- Возврат платежа Звёздами (метод Bot API `refundStarPayment` пока не подключён).
- Реальные иллюстрации карт (сейчас лица карт рисуются процедурно в SVG).
