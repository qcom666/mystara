# Переезд на базу данных в РФ: пошаговая инструкция

Цель: хранить данные граждан РФ в PostgreSQL на территории РФ (152-ФЗ, ст. 18, ч. 5) и переключить на неё
сайт, бот и Mini App. Код к этому готов: нужны только база, несколько переменных окружения и redeploy.

Что уже умеет приложение:

- подключаться к базе по TLS со строгой проверкой корневого сертификата хостера (`DATABASE_SSL_CA`);
- применять миграции из `prisma/migrations` на пустой базе (проверено на PostgreSQL 18);
- входить по e-mail и паролю или через Telegram (на сайте через виджет, в Mini App автоматически);
- удалять аккаунт и личные данные по кнопке в личном кабинете;
- сбрасывать старые сессии, если пользователя нет в новой базе;
- ограничивать частоту запросов и писать ошибки структурным журналом.

## Важно про коммиты

Vercel блокирует деплой, если у последнего коммита автор не привязан к аккаунту GitHub («couldn't find a
Git account for the commit author»). На новом компьютере до первого коммита задайте автора в репозитории:

```bash
git config user.name "ваше имя на GitHub"
git config user.email "почта, привязанная к GitHub"
```

## 1. Создать базу у хостера

Подойдёт любой управляемый PostgreSQL в российском дата-центре (Timeweb Cloud, Selectel, Yandex Cloud и т. д.).

- Версия PostgreSQL 16 или новее, регион: Москва или Санкт-Петербург.
- Шифрование соединения (TLS) включено.
- Автоматические резервные копии включены.
- Включён внешний доступ (публичный IP): у Vercel нет фиксированных адресов, поэтому доступ открывается
  по паролю и TLS. Пароль длинный и случайный, отдельный пользователь только под это приложение.
- Пользователь базы может создавать таблицы (нужен для `prisma migrate deploy`).

Записать: хост, порт, имя базы, пользователя, пароль и корневой сертификат (PEM), если хостер его выдаёт.
Подключаться по имени хоста, а не по IP: проверка сертификата сверяет имя.

Хостера, регион и дату нужно будет вписать в политику конфиденциальности (см. шаг 8).

## 2. Проверить подключение с этого компьютера

```bash
export DATABASE_URL="postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:ПОРТ/ИМЯ_БАЗЫ"
export DATABASE_SSL_CA="$(cat путь/к/корневому-сертификату.pem)"   # если хостер выдал сертификат
npm run db:check
```

Скрипт печатает версию сервера, пользователя, признак шифрования, число таблиц, применённые миграции и
среднюю задержку запроса. Пароль не выводится. Код выхода 2 означает, что соединение не зашифровано.

## 3. Создать таблицы

С теми же переменными:

```bash
npx prisma migrate deploy
npm run db:check
```

В конце должно быть 15 таблиц и 4 применённые миграции. На Vercel это же выполняет `vercel-build`
при каждой сборке: он применяет только ещё не применённые миграции.

## 4. Переменные окружения Vercel (Production)

Проект `taro_project` → Settings → Environment Variables. Секреты вносите сами.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | адрес новой базы |
| `DATABASE_URL_UNPOOLED` | тот же адрес, если у хостера нет пулера соединений |
| `DATABASE_SSL_CA` | текст сертификата (PEM целиком; допустимы `\n` вместо переводов строк или base64) |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | имя бота без `@` |
| `ADMIN_TELEGRAM_IDS` | ваш Telegram ID (администратор определяется по нему) |
| `TELEGRAM_BOT_TOKEN` | новый токен бота после перевыпуска |

Переменные `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` больше не используются: их можно удалить.
Интеграцию Neon нужно отключить от Production, иначе она подставит старый `DATABASE_URL`.
`NEXT_PUBLIC_*` подставляются при сборке, поэтому после изменений нужен новый деплой.

## 5. Настройки в @BotFather

- `/setdomain` → выбрать бота → указать домен сайта (для входа на сайте через Telegram).
- Если менялся токен: заново зарегистрировать вебхук (`/api/telegram/webhook`, секрет
  `TELEGRAM_WEBHOOK_SECRET`) и проверить адрес Mini App.
- Для ссылок приглашения в Mini App (`t.me/<бот>?startapp=ref_...`) у бота должно быть настроено основное
  мини-приложение: `/mybots` → бот → Bot Settings → Configure Mini App → указать адрес сайта. Без этого
  ссылка откроет только чат с ботом, а приглашения по ссылке на сайт продолжат работать.

## 6. Выкатить и проверить

Деплой выполняется только по команде владельца («выкатывай»). После деплоя пройти по списку:

- [ ] Главная, `/pricing`, `/tarot/cards` открываются.
- [ ] Вход на сайте через Telegram: кнопка появляется после галочки согласия, вход проходит, открывается `/reading`.
- [ ] Вход в Mini App проходит автоматически.
- [ ] Расклад сохраняется и виден в личном кабинете.
- [ ] `/admin` открывается под вашим аккаунтом и отвечает 404 без входа.
- [ ] Оплата ЮKassa на сайте небольшой суммой, возврат; оплата Звёздами в боте.
- [ ] Удаление тестового аккаунта в личном кабинете: расклады исчезают, запись об оплате остаётся.
- [ ] `npm run db:check` показывает задержку, которая вас устраивает.

Откат: вернуть прежние значения `DATABASE_URL` и убрать `DATABASE_SSL_CA`, затем redeploy.

## 7. Почта, мониторинг, бот

- **Почта для сброса пароля.** Выберите SMTP-сервис (почта домена у хостера, Яндекс 360, Mail.ru для бизнеса,
  Unisender, SendPulse), заведите ящик отправителя и задайте в Vercel `SMTP_HOST`, `SMTP_PORT`,
  `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, затем redeploy. Без этих переменных страница «Забыли
  пароль?» честно пишет, что восстановление недоступно. Почтовый сервис станет получателем адресов
  пользователей: впишите его в политику (раздел о получателях данных) и поднимите версию политики.
- **Мониторинг доступности.** Заведите проверку на `https://ВАШ_ДОМЕН/api/health` (UptimeRobot, Better Stack
  или российский аналог): 200 значит, что сайт и база отвечают, 503 значит, что база недоступна.
- **Описание, команды и кнопка меню бота.** С токеном бота в окружении выполните
  кнопкой «Обновить настройки бота» в админ-панели (`/admin`, ключами из Vercel) или
  `TELEGRAM_BOT_TOKEN=… NEXT_PUBLIC_SITE_URL=https://ВАШ_ДОМЕН npm run bot:setup` (сначала можно
  `npm run bot:setup -- --dry-run`). Скрипт задаёт команды `/start /help /docs /support`, описания на русском
  и английском и кнопку меню Mini App; с флагом `--webhook` заново регистрирует вебхук по
  `TELEGRAM_WEBHOOK_SECRET`. Токен не печатается. После выкатки автопродления Premium Звёздами выполните
  его один раз с `--webhook`: вебхук должен получать обновление `subscription` (отмена подписки в Telegram).
- **«Карта дня» и гороскоп в боте.** Подписка командой `/daily`, отписка `/daily off`, разовая карта `/card`,
  гороскоп на сегодня `/horoscope Лев` (новые команды появятся в меню бота после `npm run bot:setup`). Утренняя
  рассылка (около 9:00 МСК) включится, когда в Vercel появится `CRON_SECRET` (любая длинная случайная строка):
  расписание уже описано в `vercel.json`. На тарифе Hobby планировщик запускается раз в сутки, этого достаточно.
- **ЮKassa.** В настройках HTTP-уведомлений включить события `payment.succeeded`, `payment.canceled` и
  `refund.succeeded` с адресом `https://ВАШ_ДОМЕН/api/payments/yookassa/webhook`. Оплата засчитывается и без
  уведомлений (сайт сам проверяет платёж при возврате покупателя и раз в сутки), но с ними быстрее и надёжнее.
  `CRON_SECRET` нужен и для ежедневного обслуживания оплат (`/api/cron/billing`): сверка ЮKassa и Звёзд,
  закрытие брошенных счетов и напоминания о продлении Premium за 3 дня до конца срока.
- **Чеки самозанятого.** С каждой оплаты нужен чек в «Мой налог» (422-ФЗ, ст. 14). ЮKassa с 29.12.2025 чеки
  за самозанятых не формирует, поэтому доход регистрируется вручную: админ-панель → «Покупки» → фильтр
  «Оплачено, чек не выдан». Там видны дата оплаты, сумма и наименование услуги (кнопка «копировать название»);
  ссылку на чек из «Мой налог» (`https://lknpd.nalog.ru/…`) вставьте в поле и нажмите «Отправить покупателю»:
  чек уйдёт ботом (если аккаунт связан с Telegram) и письмом (если есть e-mail и настроен SMTP), а покупатель
  увидит его в истории покупок. Если связаться нельзя, кнопка «Отметить выданным» фиксирует, что вы передали
  чек сами. Срок — до 9-го числа следующего месяца; счётчик «Покупок без чека» на главной админ-панели
  краснеет при просрочке. При возврате оплаты аннулируйте чек в «Мой налог».

## 8. Закрыть юридические хвосты

- [ ] Вписать в политику (`src/lib/legal/privacy-policy.ts`) провайдера БД и место размещения вместо
      `[указать …]`, статус уведомления Роскомнадзора, и поднять `PRIVACY_POLICY_VERSION`
      (`src/lib/legal/operator.ts`): все пользователи заново дадут согласие.
- [ ] Подать уведомление в Роскомнадзор (Госуслуги): место хранения базы, трансграничная передача (Telegram,
      хостинг приложения).
- [ ] Показать оферту, политику и согласие юристу.
- [ ] Удалить данные из Neon (Production-база во Франкфурте) и отключить её.
